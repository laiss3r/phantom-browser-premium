## Runtime patch gap discovered during this review

The official [Chrome for Testing channel endpoint](https://googlechromelabs.github.io/chrome-for-testing/last-known-good-versions.json), timestamp **2026-10-27T19:19:40.754Z**, reports Stable **156.0.8078.47**. This branch pins **156.0.8078.4**. The difference is real; this review does **not** establish which CVEs apply or certify the older build safe.

**Stable-release blocker:** review a supported Playwright/runtime update, independently qualify archive/inventory trust and rerun native/profile/proxy/installed Windows gates before release. Do not just regenerate trust from a new download, point Playwright at an arbitrary executable, copy another fork's hashes, or call an older matching-major browser current. No unsafe automatic update or unreviewed binary migration is implemented in this stage.

## Supported coherent configuration policy

- Default/native UA is preferred. If explicitly supplied, UA must identify the bundled desktop x64 OS/runtime (exact or standard reduced version), with no conflicting repeated browser-version tokens, mobile/ARM/32-bit/other-family claims.
- Validate low/high-entropy platform, full runtime version, architecture, bitness, mobile and WOW64 when observed. Missing hints are unavailable, not successful verification. Full host-build platformVersion fidelity remains uncertified, especially custom-UA-derived metadata.
- Keep explicit viewport/screen containment, stable DPR, locale/timezone and color/motion preferences. Geolocation requires explicit grant and coordinates; diagnostics only read already-granted location with a deadline.
- Coherent reference configurations already exercised by the real suite: native desktop 1280×800, en-US/UTC/DPR1; controlled desktop en-GB/Africa-Nairobi/DPR1.25; explicit screen1400×900/viewport1000×700 preference test; independent startup/session and opt-in geo configurations. These are documented test configurations, **not** a library of purported physical device identities. No OS/hardware/graphics claims are generated from window size.
- CPU/device memory/WebGL/canvas/audio/fonts/media are native observations. Linux STUN still sends loopback UDP with the requested policy, including a profile with actual HTTP-proxy forwarding; the setting is experimental, not a firewall/no-leak promise.
